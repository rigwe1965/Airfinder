# Airfinder

A flight search and booking web app with a customer area and a staff portal. Python (Flask) backend, plain HTML/CSS/JavaScript frontend, SQLite by default.

> **Important:** flight data is **generated by a built-in mock engine** (`backend/services/mock_flights.py`): routes, times, fares and flight status are deterministic samples, not a live airline feed. Natural-language search ("Lagos to London next Friday business") is **rule-based parsing** (`backend/services/ai_search.py`), not a language model. No payment is taken. Use it as a demo or as a base to connect real suppliers.

## What it does

- Customer sign-up, login, password reset, own bookings and profile
- Flight search: one-way, return, multi-city, natural-language search, flight status lookup
- Booking flow with server-signed fare quotes (prices cannot be changed in the browser)
- Staff portal at `/admin/` with roles: `super_admin`, `admin`, `agent`, `finance`, `customer`
- Finance summary (markup, service fee, commission settings)
- Security log, rate limiting (per IP and per account), strict content-security rules (no inline scripts)
- Prices shown in EUR

## Run it on your computer

You need Python 3.11 or newer.

```
copy .env.example .env      # Windows   (macOS/Linux: cp .env.example .env)
```

Edit `.env`: set `SECRET_KEY`, `JWT_SECRET`, `SUPER_ADMIN_EMAIL` and `SUPER_ADMIN_PASSWORD` (the app refuses to start without the last two). Then:

```
start.bat                   # Windows, or:  ./start.sh   (macOS/Linux/Git Bash)
```

Open http://localhost:5000. Staff sign in at `/admin/login.html` with the super admin account and must change the password on first login.

Optional: `python seed_demo.py` adds demo customers and bookings. `python reset_admin.py` resets the super admin password.

## Tests

```
pip install -r requirements.txt
python -m pytest backend/tests
```

(`psycopg2-binary` is only needed for PostgreSQL; leave it out locally if it fails to install.)

## Settings

All settings are environment variables; see `.env.example` and `backend/config.py`. Real secrets live only in `.env`, which is never committed. Mail (password reset, staff invites) needs `MAIL_USERNAME` and `MAIL_PASSWORD`; without them nothing is sent.

## Deploy

`render.yaml` describes a Render web service (gunicorn). The Facyke demo server builds a container from this repository using recipes kept in the ProjectsDashboard repository. Production uses PostgreSQL through `DATABASE_URL`.
